## 二、写作原则

1. **直接入题**：开头不放长引用说明，参考来源统一放文末。
2. **一环一图**：每个环节都在正文中预留图片位置，用视觉类比帮助读者理解。
3. **先作用，后直觉原理**：每环先讲“解决什么问题”，再讲技术机制。
4. **术语少而准**：重点术语保留 **token、MCP、RAG、ReAct、prompt injection**；其余只做直觉解释。
5. **所有关键论断可溯源**：vLLM、Anthropic、MCP、RAG、ReAct、OWASP 等均放入文末参考来源。
6. **明确边界**：不说“模型查数据库”“模型执行工具”“RAG 消灭幻觉”“MCP 让模型变聪明”“上了 Agent 就更高级”。

## 四、逐节细纲

### 0. 引子

标题下方先放全流程加工处理图，用少量中文标签概括“生成文字 → 跑成服务 → 组织信息 → 请求执行 → 接入资料 → 循环推进 → 安全兜底”。随后用真实任务开场：“帮我查几份资料，整理成结论，再发给同事。”强调表面看 AI 像是在自己办事，但真正变化是工程系统给模型接上了能力。

### 1. 环节一：模型本体

说明大语言模型的基本动作是预测下一个 **token**。用“打字机逐格吐出 token”做视觉类比。边界：模型不是在数据库里查答案，它的知识来自训练时压进参数的模式，所以会出现看似合理但错误的输出。

### 2. 环节二：推理引擎

澄清 inference 与 reasoning 的区别。推理引擎把模型跑成服务，处理缓存、显存和并发。保留 vLLM / PagedAttention 官方数据：传统系统会浪费 60%–80% 显存，PagedAttention 将浪费降至 4% 以下。

### 3. 环节三：上下文编排

解释为什么聊天看起来连续：系统每轮都会把任务、历史、规则、工具说明和资料重新组织到上下文里。补充 Lost in the Middle：上下文不是越长越好，关键信息被埋在中间会降低利用效果。

### 4. 环节四：工具接口

全文转折：模型不亲自执行工具，而是输出工具名和参数。用“点菜单”类比澄清：模型是顾客，外部代码是后厨。MCP 用作标准接口的说明，不能写成模型能力本身。

### 5. 环节五：知识与记忆

RAG 是开卷考试，记忆是可延续的笔记本。补充 Lewis et al. 对参数化记忆 / 非参数化记忆的区分。边界：RAG 能降低幻觉，不能消灭幻觉。

### 6. 环节六：闭环控制

把前面的能力串成运行中的闭环：观察 → 判断 → 行动 → 结果回流。用 ReAct 作权威锚点。必须讲 workflow 与 agent 的边界：固定流程更适合 workflow，只有路径无法提前写死时才需要 agent。

### 7. 环节七：验收与护栏

冷静段。保留三点：错误会复合；外部资料可能带来 **prompt injection**；高风险动作必须有人审、权限边界和审计。强调能跑不等于能托付。

### 8. 收尾

三问判断一个 AI 产品：

1. 它只是会回答，还是能可靠调用外部工具？
2. 它用到的资料和记忆从哪里来，能不能追溯？
3. 它的自动循环有没有边界、审计和人工确认？
