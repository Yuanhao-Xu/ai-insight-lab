## 第 1 环「模型打字机」——大模型本体 · 深度调研报告

## 1. 一句话定位 + 它在全链路中的位置

**一个训练好的大语言模型（Large Language Model, LLM），本质上是一个被巨量文本参数化压缩后的统计预测引擎**：给定已有 token 序列，计算出词表上所有 token 的概率分布，再从中采样出下一个 token；反复迭代，生成连贯文本。

全链路位置：LLM 本体是整个 AI 工程栈的**最底层基础**——推理引擎（Inference Engine）要运行它，智能体（Agent）要调用它。没有这个「打字机」，后续一切无从谈起。它完成的唯一工作是 **next-token prediction**；让它「像个助手」还需要后训练（post-training）改造，但那是第 2 环的故事。

---

## 2. 通俗讲法（破壁课用）：3 个最佳比喻

### 比喻 A：「超强手机键盘联想词」
Jay Alammar 在《The Illustrated GPT-2》（jalammar.github.io）中写道：
> "The GPT-2 is basically the next word prediction feature of a keyboard app, but one that is **much larger and more sophisticated**."

手机输入法在你打出「今天天气」后，会弹出「不错」「很好」等候选词——GPT 做的是同一件事，只是它读过半个互联网，候选词背后是数百亿参数支撑的概率分布，而不是简单的频率统计。

### 比喻 B：「互联网文档模拟器」
Andrej Karpathy 在 2025 年 2 月的 3.5 小时视频《Deep Dive into LLMs like ChatGPT》中反复强调：
> 预训练产出的 **base model**（基础模型），是一个「**internet document simulator**（互联网文档模拟器）」——它能续写任何风格的文字，因为训练数据本身就是互联网的横截面。

（注：Karpathy 另有「it dreams internet pages / 它在梦见互联网页面」的说法，出处同一视频）

### 比喻 C：「最强自动补全 / Autocomplete on Steroids」
这是 Karpathy 在多个场合使用的表达，也是《Intro to Large Language Models》（2023 年 11 月 YouTube，播放量数百万）中的核心心智模型：把 LLM 理解为「打了激素的自动补全」，既抓住了自回归的本质，又传达了规模带来的质变。Stephen Wolfram 在《What Is ChatGPT Doing … and Why Does It Work?》（writings.stephenwolfram.com, 2023 年 2 月）中表述了同一直觉：
> "When ChatGPT writes an essay, it's essentially asking over and over again **'given the text so far, what should the next word be?'**—and each time adding a word."

## 3. 硬核机制（报告用）

### 3.1 分词：模型看到的世界单位是 Token

LLM 的输入不是字符、不是词，而是 **token**（词元）——通常是子词（subword）片段。

现代主流算法是 **BPE（Byte Pair Encoding，字节对编码）**，由 Sennrich, Haddow, Birch 在 ACL 2016 论文《Neural Machine Translation of Rare Words with Subword Units》引入 NLP 领域。核心思路：从单字符出发，反复合并语料中出现频率最高的相邻符号对，直到词表达到预设大小。

实际效果举例：
- `"ChatGPT"` → `["Chat", "G", "PT"]`（3 个 token）
- `"tokenization"` → `["token", "ization"]`（2 个 token）
- `"你好"` 在中文语境下可能是 1 个 token，也可能被拆成 2 个

GPT-2/GPT-3 的词表约 5 万 token；GPT-4 使用 **tiktoken 的 cl100k_base**，词表约 **10 万 token**，对代码、中日韩文字的编码效率显著提升（同等文本所需 token 数减少约 38%）。

**关键推论**：计费、上下文长度（context length）、速度，全部以 token 为单位计算，不是字数或词数。

---

### 3.2 前向推理（Inference）全流程：概念级

```
输入 tokens
    ↓
Token Embedding（词嵌入）
    ↓  ——每个 token → 高维向量（如 768 / 4096 维）
Position Embedding（位置编码）
    ↓  ——告诉模型每个 token 在序列中的位置
Transformer Blocks × N 层
    ├── Multi-Head Self-Attention（多头自注意力）
    │       ——让每个 token 的向量"吸收"上下文信息
    └── Feed-Forward Network（前馈网络）
            ——逐位置的非线性变换，存储"事实"
    ↓
最后一层输出向量
    ↓
Linear Projection → Logits（未归一化得分，词表大小维度）
    ↓
Softmax → 概率分布 P(next token | 已有 tokens)
    ↓
Sampling（采样）——按概率或 top-k / top-p 采样出下一个 token
    ↓
将新 token 追加到序列，循环上述步骤 → 自回归生成
```

**核心数学直觉（不推公式）**：

- **Embedding**：把离散 token ID 映射为连续向量；语义相近的 token，向量在高维空间中距离相近（3Blue1Brown 《But what is a GPT?》对此有经典可视化）
- **Self-Attention（自注意力）**：每一层让每个 token 的向量「看到」序列中其他所有 token，动态加权融合上下文——这就是 Vaswani et al. 2017《Attention Is All You Need》（arXiv 1706.03762，被引约 10 万次）的核心贡献
- **Logits → Softmax**：线性层输出对词表每个 token 的原始得分（logits），经 Softmax 归一化为总和为 1 的概率分布；温度参数（Temperature）控制分布的「尖锐 / 平缓」程度——温度趋 0 时几乎总选概率最高的 token（贪心解码），温度升高时则更多采样低概率 token（增加随机性与多样性）
- **Masked Self-Attention（掩码自注意力）**：GPT 系列的 decoder-only 架构，预测第 t 个 token 时只能看到第 1 到 t-1 个 token，确保自回归的因果性（Jay Alammar 《The Illustrated GPT-2》有精确图示）

---

### 3.3 自回归：为何像「打字机」

**Autoregressive（自回归）** 生成意味着：模型每次只生成一个 token，然后把这个 token 追加进输入序列，重新做一次前向推理，再预测下一个。从左到右，逐 token，没有回头路。

这一特性解释了几个现象：
- 为何 LLM 无法「修改已生成的字」（除非重新生成）
- 为何生成速度受限于串行推理（这也是推理引擎要优化的核心瓶颈，将在第 2 环展开）
- 为何它有时会「把自己写进死胡同」——因为每一步决策仅依赖此前生成的 token，无前瞻性

---

### 3.4 Base Model vs. Chat/Instruct Model 的高层区别

**预训练（Pretraining）**：在数万亿 token 的互联网文本上，用 next-token prediction 作为自监督目标训练模型，产出 **base model**（基础模型）。它只会续写——给它「北京是」，它可能续写「中国的首都，也是...」，也可能续写一篇相关的维基百科词条。它不会「回答问题」，因为从未被训练去「回答」。

**后训练（Post-training）**——包括 SFT（Supervised Fine-Tuning，有监督微调）、RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）等——把这台「续写机」改造成「助手」，让它遵循指令、礼貌、拒绝有害内容。具体机制留待系列第 2 环展开；此处只需记住：**chat model 是 base model 经过特定行为塑形的结果，底层推理机制完全相同**。

## 6. 常见误解与「经不起推敲」的坑

**误解 1：「它在数据库里查答案」**
错误。LLM 没有可检索的外部知识库，知识以「**parametric memory（参数化记忆）**」的形式分布在数十亿个权重中，是训练数据的有损压缩（lossy compression），而非索引查询。这也是它会「幻觉」（hallucination）的根本原因。

**误解 2：「它预测下一个词（word）」**
不精确。应为「预测下一个 **token**」。token 是子词片段，中文的一个字可能是一个 token，也可能两个汉字共用一个 token；英文「tokenization」被切成 `["token", "ization"]`。

**误解 3：「它理解了语义 / 它真的在思考」**
高度有争议。Bender et al. 2021「stochastic parrot」论文明确指出，流利的形式输出不等于语义理解。**写推文时应将「它理解了」处理为未经证实的主张，而非事实。**

**误解 4：「它是在从左到右'搜索'最佳答案」**
不准确。推理时没有搜索过程，只有一次前向传播（forward pass）计算概率分布，然后采样。

**误解 5：「温度 = 0 时模型最准确」**
表述不精确。温度 = 0 是贪心解码（每步选概率最高 token），输出确定性最强，但不一定最准确——有时贪心路径会陷入重复或次优解。

**误解 6：「Chat model 和 Base model 是两种不同架构」**
错误。二者共享完全相同的 Transformer 架构，差异只在权重（参数值）。

**「随机鹦鹉」术语使用注意**：这是 Bender et al. 的**批评性术语**，带有明确的政治与伦理立场，不应被用作中性描述词。

## 7. 与下一环（推理引擎）的衔接逻辑

「打字机」的自回归特性揭示了一个性能瓶颈：每生成一个 token，都需要完整地做一次前向推理，且对已有 token 的注意力计算（KV Cache）需要被高效复用——这正是**推理引擎（Inference Engine）** 存在的核心理由：如何在 GPU/TPU 上把这台「打字机」的击键速度从每秒个位数 token 推向数百 token，同时控制显存、延迟与吞吐量之间的三角权衡。
