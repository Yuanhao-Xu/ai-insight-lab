## 1. 一句话定位 + 它在全链路中的位置

**工具调用与结构化输出** 是大语言模型从「文字生成器」进化为「任务执行者」的关键转折枢纽：模型在此环节学会以**严格格式化的结构化请求**来「委托」外部能力，而非自行执行——它的输出不再只是自然语言，而是一份机器可解析、可路由、可执行的**工具调用合同**。

```
[1] 打字机 → [2] 推理引擎 → [3] 上下文工程
   → [4] 工具调用 + 结构化输出 ← 你在这里（「说」到「能请求做事」的桥）
   → [5] 知识与记忆（RAG/Memory）→ [6] 智能体（Agentic Loop）
```

**本环核心身份**：模型至此具备「外包能力」——可请求调用计算器、数据库、API、搜索引擎，但**执行者永远是外部代码（harness/client app），模型本身只是打字**。

## 2. 通俗讲法（破壁课用）

**比喻 A：「点菜单」模型（最直觉）**
模型是顾客，工具是菜品。顾客不进厨房自己炒菜——他只在菜单（JSON Schema）上勾「`get_weather(city=北京)`」，递给服务员（harness），厨房（真实 API/代码）做完，服务员端回结果，顾客再决定下一道菜。**模型永远是点菜的顾客，不是厨师。**
> 出处：Anthropic 官方文档「Claude responds with a structured call that **your application executes**」。

**比喻 B：「USB-C 接口」标准（MCP 专用）**
工具一多，每个 AI 产品都要单独对接每个外部服务，像每台设备都有专属充电口。MCP（Model Context Protocol）就是 AI 世界的 **USB-C 接口标准**。
> 出处：modelcontextprotocol.io 官方原话：「Think of MCP like a USB-C port for AI applications.」

**比喻 C：「模具铸造」（约束解码专用）**
普通生成像往沙滩浇水，形状随机；**约束解码（Constrained Decoding）** 先放好铸模（JSON Schema），每个 token 采样前把「会破坏结构合法性」的选项屏蔽掉（logit mask）。

## 3. 硬核机制（报告用）

### 3.1 Function Calling / Tool Use 的三轮 Turn 协议
1. **Turn 1（用户 → 模型）**：调用方在请求中附带工具列表（名称、描述、JSON Schema 参数）。
2. **Turn 2（模型 → harness）**：模型判断是否调用（`tool_choice: auto`，或强制）。若调用，**模型停止生成自然语言**，输出 `stop_reason: "tool_use"` 的结构化响应块（工具名+参数 JSON）——**这是模型的全部工作**，它并不执行任何函数。
3. **Turn 3（harness 执行 → 模型）**：开发者代码执行，结果以 `tool_result` 注入对话历史，模型据此生成最终回复。
循环多轮即 **Agentic Loop**。Anthropic 的 Programmatic Tool Calling：Claude 生成 Python 代码编排多工具，中间数据不进上下文——75 工具基准中输入 token 减少约 **38%**，准确率不变。

### 3.2 结构化输出 / JSON Mode / 约束解码
| 方案 | 保证 | 机制 |
|---|---|---|
| Prompt Engineering | 无强保证 | 依赖模型遵从 |
| JSON Mode | 保证合法 JSON 语法 | 引导但不强制 |
| Structured Outputs / 约束解码 | 保证与 JSON Schema **完全匹配** | Token 级强制约束 |

约束解码技术：推理引擎在每步采样前根据已生成序列和目标 Schema 计算 **logit mask**，将违反 Schema 的 token logit 设为 -∞，再从合法候选采样。本质是在语法状态机（FSA）/ 上下文无关文法（CFG）约束下的条件采样。
- **outlines**（dottxt-ai/outlines，约 14.1k star）：支持 JSON Schema/regex/CFG。
- **guidance**（guidance-ai/guidance，约 19k star，Microsoft Research）：底层 llguidance 引擎，2025-05 起被 OpenAI Structured Outputs 采用。
- **OpenAI Structured Outputs**（2024-08，gpt-4o-2024-08-06，strict:true）：Schema 遵从率从旧版 gpt-4-0613 的 <40% 提升到 **100%**。

### 3.3 MCP（Model Context Protocol）
- **发布**：2024-11-25，Anthropic 工程师 David Soria Parra、Justin Spahr-Summers 设计开源。
- **2025-12-09**：Anthropic 将 MCP 捐给 **Agentic AI Foundation（AAIF，Linux Foundation 旗下）**，与 Block（goose）、OpenAI（AGENTS.md）并列三大创始项目；联合支持方 Google、Microsoft、AWS、Cloudflare、Bloomberg。
- **解决的核心问题（M×N 碎片化）**：之前 M 个模型 × N 个工具每对都要定制连接器；MCP 压成 M+N。
- **三层架构**：MCP Host（AI 应用）/ MCP Client（协议客户端）/ MCP Server（暴露 Tools、Resources、Prompts）。通信层 JSON-RPC 2.0，支持 stdio（本地）和 SSE（远程）。
- **生态规模**（捐赠时）：月 SDK 下载约 **9700 万**次，活跃 server **1 万+**个；已被 ChatGPT、Claude、Cursor、Gemini、Microsoft Copilot、VS Code 采用。

### 3.4 论文谱系
- **Toolformer**（Meta，2023-02，arXiv:2302.04761，NeurIPS 2023）：首次展示语言模型可**自监督**学会何时/如何调用 API（计算器、QA、搜索、翻译、日历 6 类）；6.7B 模型在多项 zero-shot 基准超越大得多的模型。
- **Gorilla**（UC Berkeley，2023-05，arXiv:2305.15334）：解决 LLM 调真实 API 时**幻觉出错误参数/不存在函数**的问题，引入检索增强；孵化 **Berkeley Function Calling Leaderboard（BFCL）** 标准评测。

## 6. 常见误解与「经不起推敲」的坑

1. ❌「模型自己运行了工具/代码」。✅ 模型只输出结构化请求，执行的是 harness（或服务端的独立执行层）。
2. ❌「开了 Function Calling 就保证合法 JSON」。✅ Function Calling 与结构化输出正交；要 100% 合规需约束解码。
3. ❌「MCP 让模型变聪明」。✅ MCP 是接口标准（类 USB-C/HTTP），不增智能。
4. ❌「Toolformer 证明模型能自主用所有工具」。✅ 仅在预定义少量简单 API 上、靠自监督微调；不解决幻觉不存在 API（那是 Gorilla 要解决的）。
5. ❌「Anthropic 拥有 MCP，有垄断风险」。✅ 已捐给 Linux Foundation，厂商中立。

## 7. 与上一环（上下文）/ 下一环（知识与记忆）的衔接逻辑

**承上**：当模型发现当前上下文信息不足（如「北京今天天气」不在 context 里），Function Calling 给它一个「出口」——不必幻觉猜测，而是打出「工具调用票据」，由 harness 获取真实数据注入 context。**工具调用是上下文的动态扩充机制。** 同时工具 schema 本身消耗 context，故有 Programmatic Tool Calling / Tool Search 来压缩开销。
**启下**：① RAG 本质是工具调用的特例（向量库查询封装成一个工具，模型发出检索请求）；② MCP 将成为知识接入的标准化管道。一句话：上下文是此刻的舞台，工具调用是获取临时道具的机制，知识与记忆是永久仓库——MCP 是连通三者的标准化货运协议。
