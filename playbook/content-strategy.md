# AI 编程 / 智能体公众号 · 核心内容设计

---

## 一、定位

**一句话**：在 AI 时代，把想法造成可靠的软件——既讲清 AI 编程与智能体的原理，也用 vibe coding 做出可复现的项目。

| 栏目 | 定位 | 读者 | 作用 |
|---|---|---|---|
| **AI 概念科普** | 破概念门槛的入门科普 | 小白、产品、初级程序员、AI 爱好者 | 引流拉新 |
| **AI 技术深潜** | 模型 / 推理 / Agent 工程硬核 | 程序员、算法 / AI 工程师 | 立威、沉淀高质量粉 |
| **AI 项目实战** | Vibe Coding 做可复现 demo | 想动手用 AI 做东西的人 | 特色、传播、留存 |

**三条护城河**：① 真实生产经验——「踩过的坑 + 能跑的代码」，回应「答案差一点对、不敢上线」的痛点；② 既讲应用又讲底层——下探 RAG、推理加速、Agent 架构，低竞争区；③ 抓最新叙事——SDD、Loop Engineering 等热点第一时间讲透。

## 二、栏目设计

### 栏目一 ·《AI 概念科普》（入门）

**三条写作建议**（已由首篇《会聊天，不等于能办事》验证）
1. **一篇只讲透一个核心概念**——首篇全文只讲 Chatbot 与 Agent 的「动嘴 vs 动手」。
2. **一个真实场景 / 类比贯穿全文**——用「订一次出差」贯穿；类比要做概念工作（多工具编排、中途应变），不是随手举例。
3. **二元对比比中间层更锋利**——砍掉「Workflow」中间档，强化二元对照；再给读者一把可操作的「尺子」。

**范文骨架**（从首篇逆向提炼）
真实痛点场景开场 → 点破核心概念 + 辨伪（给一把「尺子」）→ 同场景对比讲透 → 掀引擎盖讲原理（配图 / 比喻、多源精确归因）→ 冷静章节：成本·风险·边界（务实不浮夸、带真实数据）→ 如何选 / 怎么用 → 下一步看什么。

**选题清单**

| 方向 | 选题示例 |
|---|---|
| Agent 基础 | 《Chatbot 和 Agent 到底什么区别？用一次出差讲清》（首篇 ✓） |
| 工具对比 | 《Claude Code、Cursor、Codex、Copilot 怎么选？(2026)》 |
| Vibe Coding | 《一句话让 AI 写项目，为什么有时能成、有时很坑？》 |
| 工作流 | 《AI 编程 4 种用法：问答、补全、改代码、自动交付》 |
| 概念扫盲 | 《Tool Calling、MCP、Workflow、Agent 分别是什么？》 |
| 最新热点 | 《Loop Engineering：从「写提示词」到「写循环」》 |
| 风险科普 | 《AI 生成的代码为什么总「看起来对」？》 |

**固定子栏目「一句话需求挑战」**：同一真实任务（修 bug / 加 API / 做小页面）分别丢给 Claude Code / Cursor / Codex，比时间、改动行数、可控性、能否跑起来，输出评分表；标注测试日期与模型版本。

| 分组 | 选题示例 |

### 栏目三 ·《AI 项目实战》

**核心机制**：做出 demo → 反向蒸馏 **Prompt Recipe** → 读者复制提示词、用自己的 AI 工具生成相似项目（「代码 → 提示词」逆向，让读者正向产出）。

**Prompt Recipe 标准做法**（不承诺「一键复刻」）
1. 逆向产物是一份「迷你 spec」：角色 + 目标 + 技术栈约束 + 功能边界 + **验收标准**（测试 / 类型 / 清单做门禁）。
2. 三层提示词：一句话版（展示）/ 稳定复现版（含约束验收）/ 迭代修复版（跑不起来时追问）。
3. 钉死可复现条件：模型 + 版本 + 日期。
4. 自测复现：干净上下文重跑 1–3 次，如实写「哪里好、哪里飘」。
5. 附「工程化升级清单」：接真实 API / 加数据库 / 错误处理 / 部署 / 安全 / 评测。

**实战文固定 8 段**：①效果展示（先给结果截图）②为什么做 ③功能拆解（表格化边界）④技术栈选择 ⑤核心代码（只讲关键，全量放 GitHub）⑥Vibe Coding 构建过程（真实多轮——栏目特色）⑦Prompt Recipe（三层）⑧扩展作业。

**Demo 清单**（按价值与可传播性排序）

| 期 | 项目 | 价值 |
|---|---|---|
| 1 | AI 公众号选题助手 | 自身可用、强相关，主推 |
| 2 | NL2SQL「问数」助手 | 核心强项、高价值 |
| 3 | AI 数据分析助手(Excel→可复现) | 受众广 |
| 4 | AI 简历优化器 | 易传播 |
| 5 | AI 周报 / 日报生成器 | 办公自动化 |
| 6 | RAG 知识库问答 Demo | Agent / RAG 入口 |
| 7 | AI 代码 Review 助手 | 贴合程序员 |
| 8 | AI GitHub Issue 总结器 | 开发者场景 |
| 9 | MCP 工具调用 Demo | Agent 工程化 |
| 10 | AI 旅行规划器 | 破圈、易懂 |

**边界**：不做登录 / 支付 / 复杂权限 / 生产级部署，优先 mock 数据，文末给「如何升级成生产项目」。

## 三、内容形式规范

**字数**：入门 / 观点 1500–2500；项目实战 3000–5000；硬核深度 5000–8000。

**标题**：≤25 字、关键词前置、含数字 / 痛点。
- ✗《Claude Code 使用教程》→ ✓《我让 Claude Code 修一个真实 Bug：做对 70%，剩下 30% 最危险》
- ✗《什么是智能体》→ ✓《Chatbot 不是 Agent：一个会查数据、调工具、自己复盘的最小智能体》

**难度标签**（每篇）：`阅读难度：入门 / 进阶 / 硬核 ｜ 适合读者：… ｜ 预计阅读：N 分钟`

**风格建议**（首篇已验证）
- 一句话结论开头，真实场景切入（不抽象）；开头 3 秒抓人，每 ~300 字一个钩子。
- 「技术负责人写内部实践手册」语气：少用「颠覆 / 革命」，多用「这个场景有效」「这里会失败」「这步必须人审」。
- 每个 claim 必有数据支撑 + 多源精确归因。
- 加粗关键英文术语（**agent washing**、**prompt injection**）。
- 图精不宜多，每篇以 1 张架构 / 流程 / 对比图为主。
