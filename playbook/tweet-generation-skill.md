# 推文生成 Skill

产出一篇完整的公众号长图文。先定类型，再套「通用规范 + 该类型特异规范」，配图后按文件夹结构落盘。

## 一、产出流程

1. **定类型**：概念科普 / 技术深潜 / 项目实战，取对应卡片（见三）。
2. **成文**：遵循通用规范（二）与该类型的篇幅、语体、骨架。
3. **配图**：通读定位置，写 `assets/生图提示词.md`（见 2.3）。
4. **落盘**：按 2.1 文件夹结构，按需建目录。

## 二、通用规范（三类共用）

### 2.1 文件夹结构（按需扁平）

每篇一个文件夹，以标题命名，按需建子目录——没有对应内容就不建该文件夹。

```
<文章标题>/
  <文章标题>.md     # 正文，直接放根目录
  assets/           # 图片 + 生图提示词（有图才建）
  references/       # 参考 / 调研资料（有才建）
  <其他>/           # 其他附件按主题另建一层（按需）
```

正文始终在根目录；图片与「生图提示词.md」放 `assets/`，正文按 `assets/xxx.png` 引用；结构尽量一层，不为空内容预留文件夹。

### 2.2 语言与表达

- **语气**：像「技术负责人写内部实践手册」。少用「颠覆 / 革命」，多用「这个场景有效」「这里会失败」「这步必须人审」。
- **开头**：一句话结论 + 真实场景切入，3 秒抓人；此后约每 300 字一个钩子。
- **类比优先**：抽象概念尽量用一个贴切类比落地，替代干讲；类比要做概念工作，不是随手举例。
- **可信**：claim 配数据与精确归因，数字标注口径 / 时点；不可靠的数据宁可不用——成稿不留核验、口径、调研口吻等过程性表述。
- **术语**：关键英文术语加粗，中文为主、英文点到。
- **标题**：≤25 字，关键词前置，含数字 / 痛点。
- **引用来源**：若开头用一段 `>` 引言，只简短说明本文参考的论文 / 博客 / 解读来源；无来源则不加。

### 2.3 配图与生图

**判断在哪配图**（通读成稿后）：封面 / 开篇主图；核心概念处（二元对比、结构拆解、流程循环用对比 / 结构 / 流程图）；抽象比喻处（贯穿全文的类比落为概念图）。不配图：纯叙述、可用表格替代、信息密度低处。**数量随篇幅与类型调节**（见各类型卡片），图为讲清机制服务，宁缺毋滥。

**怎么写生图提示词**（写入 `assets/生图提示词.md`，结构为「一段全局统一风格 + 每图一节」）：

- **全局统一风格段**：定义画风、主色与背景、线条色、图标 / 人物造型、文字处理原则；多图复用同一套（配色明度、线条粗细、造型、字体）。
- **每图一节**：文件名 `figN-keyword.png`（与正文引用一致）/ 用途 / 核心表达（一句）/ 生图提示词（放 ```text 块）。
- **单图提示词骨架**：① 画风与用途定调 → ② 主题一句话 → ③ 画面要表达的要素与关系 → ④ 构图自由度（给约束不锁死）→ ⑤ 重复全局风格要求 → ⑥ 文字处理（优先无文字，关键标签后期叠加，必须有字则极少且不变形）。

## 三、文章类型（特异规范）

每张卡片含：篇幅 / 语体 / 定位 / 骨架 / 配图。未提供范文的类型按其骨架成文。

### A. 概念科普（入门）
- **篇幅 / 语体**：1500–2500 字；偏口语、亲和。
- **定位**：为小白破概念门槛，一篇只讲透一个核心概念。
- **骨架**：真实痛点开场 → 点破概念 + 辨伪（给一把「尺子」）→ 同场景对比讲透 → 掀引擎盖讲原理（配图 / 比喻）→ 冷静章节：成本·风险·边界 → 如何选 / 怎么用 → 下一步预告。
- **推荐**：一个真实场景 / 类比贯穿全文；二元对比比中间层更锋利。
- **配图**：1–3 张，1 张主图为骨干。

### B. 技术深潜（硬核）
- **篇幅 / 语体**：5000–8000 字；相对书面、克制、精确，术语与公式按需保留并配直觉解释。
- **定位**：模型 / 推理 / 工程机制的硬核拆解，事实锚定论文、官方文档、代码库。
- **骨架**：机制问题切入 → 概念与边界澄清 → 分层 / 分组件逐环拆解 → 关键权衡与选型 → 工程化建议与意义。常见误区并入相关章节顺带点出，不单列一节。
- **配图**：适量增加，每个核心机制可配 1 张（约每 800–1200 字 1 张）。

### C. 项目实战
- **篇幅 / 语体**：3000–5000 字；务实、可操作。
- **定位**：做出可复现 demo，反向蒸馏可复用的提示词配方。
- **骨架（固定 8 段）**：效果展示（先给结果）→ 为什么做 → 功能拆解（表格化边界）→ 技术栈选择 → 核心代码（只讲关键）→ 构建过程（真实多轮）→ 提示词配方（一句话版 / 稳定复现版 / 迭代修复版，钉死模型 + 版本 + 日期）→ 扩展作业。
- **配图**：效果截图为主，辅以关键流程图。
